# structsense — core runtime.
#
#     pip install -r requirements.txt
#
# This is enough to run the ABCD/HBCD mode end to end with the calling agent as
# the model (Claude Code / Codex): read PDFs, build dictionary snapshots, verify
# quotes, map constructs, and write JSON + Markdown + Turtle. Nothing here needs a
# GPU, an API key, or R.
#
# The heavier or path-specific pieces are separate files, so a plain run does not
# drag in torch or a pile of SDKs:
#
#     requirements-llm.txt    provider SDKs — only when a framework calls an API
#                             (Pi, batch, cron; i.e. --llm-model)
#     requirements-ner.txt    HuggingFace NER ensemble (transformers + torch)
#     requirements-dev.txt    validating outputs while developing the skill
#
# Upper bounds pin the major version so a breaking upstream release cannot land in
# a rebuild unreviewed. For a reproducible environment, compile a lock file:
#     pip-compile --generate-hashes requirements.txt -o requirements.lock
#     pip install --require-hashes -r requirements.lock

# --- HTTP: concept mapping (BioPortal / OLS / local hybrid), GROBID, LLM calls ---
requests>=2.31,<3

# --- Output validation against schemas/*.json ---
jsonschema>=4.20,<5

# --- JSON repair, tier 3 -----------------------------------------------------
# scripts/json_repair.py has four tiers; tier 3 delegates to this library for
# trailing commas, single quotes and unquoted keys — the failure modes small models
# hit most. Without it that tier is skipped and more responses fall through to
# truncate-to-balanced. Note the import name (json_repair) matches the local script
# of the same name; the PyPI distribution is json-repair.
json-repair>=0.30,<1

# --- PDF text extraction -----------------------------------------------------
# input_loader tries GROBID -> pymupdf4llm -> PyMuPDF -> pdfminer.six and uses
# whichever is present. Without at least one, every PDF fails with "all PDF
# extractors failed".
#
# Figure captions and table cells are the thing that separates these backends, and
# they matter more than they sound: against a gold standard, 19 of 101 passages could
# not be located in PDF-derived text (155 annotations), and 7 papers had NO
# figure-caption text at all. Captions are in scope for cell extraction and among the
# densest passages in a paper.
#
#   GROBID        best structure, reconstructs captions and tables properly — but it
#                 is a Java server on :8070 that many people cannot run.
#   pymupdf4llm   the best option that needs NO server: layout-aware Markdown that
#                 keeps captions and table structure. Pure pip, wraps PyMuPDF.
#   PyMuPDF       fast and reliable for body text; captions survive but ordering is
#                 not column-aware (input_loader passes sort=True to help).
#   pdfminer.six  pure-Python fallback for environments where PyMuPDF will not build.
#
# For an OPEN-ACCESS paper, skip all of this: `python -m scripts.fetch_fulltext
# <PMCID>` pulls publisher XML where captions and tables are first-class elements,
# needing no PDF, no server and no key. That is the only path with no caption ceiling.
pymupdf>=1.24,<2
pymupdf4llm>=0.0.17
pdfminer.six>=20231228
